<summary><strong>Manifesto against Rust and for C++ (click to expand)</strong></summary>

I hate Rust, not in a childish “I tried it once and got frustrated” way but in a principled, engineering-driven, deeply personal way, because Rust is a language built on marketing, moral superiority, and a borrow checker that treats grown adults like toddlers who cannot be trusted with a pointer, while C++ is honest enough to hand me the chainsaw, the keys, and the full legal responsibility for what happens next; the borrow checker is not a feature, it is a babysitter that makes me slower and forces every idea through a permission slip, whereas C++ treats me like an adult and expects competence, discipline, RAII, smart pointers, and actual debugging instead of a compiler sermon; Rust compile times are an insult to human life, because I should not be able to make coffee, eat lunch, question my career, raise a family, and still watch Cargo compile a project that C++ would have built before the kettle boiled; Rust’s community is a cult with a package manager, where every technical discussion becomes a sermon about memory safety and every C++ developer is treated as morally inferior for not chanting cargo, while C++ developers ship software, optimize hot paths, and do not need a support group to justify their language choice; “safe” is not the same as “correct,” because Rust will happily let you write the most logically broken banking app in human history as long as it is thread-safe, and then congratulate you on avoiding data races while the money goes to the wrong account; the unsafe keyword is the confession booth of the Rust religion, because the community spends years preaching safety and then writes unsafe blocks the moment performance matters, so the language is safe until it is not and everyone acts like that is a theological mystery instead of a design escape hatch; C++ has forty years of production scars, operating systems, game engines, trading systems, embedded devices, browsers, databases, and industrial software, while Rust has blog posts, a loud fan club, and a growing pile of rewrites still waiting for their GUI framework to stabilize; Rust has no stable ABI and somehow that is C++’s fault, because I can expose C++ through stable C ABIs and battle-tested tooling while Rust reshuffles its ecosystem and cheerfully tells you to rebuild the world every time the compiler sneezes; async Rust is a labyrinth designed by people who hate you, full of futures, pinning, executors, runtimes, and lifetimes across await points, and C++ async is ugly and dangerous too but at least it is ugly and dangerous in ways I can debug without drawing a state machine on a whiteboard and crying; Rust’s macro system is a second language nobody asked for, a summoning ritual disguised as metaprogramming, and C++ templates are horrifying but at least they are horrifying in a language with decades of tooling to understand the horror; the Rust RFC process is bureaucracy cosplaying as innovation, where every feature takes years and every decision is argued to death by a community that thinks it is a moral movement rather than a committee; Rust’s ecosystem is dependency bloat disguised as modernization, because a twelve-line project can pull in four hundred crates, three async runtimes, and a cryptographic library maintained by one person in a time zone you cannot pronounce, while C++ lets me choose my dependencies, my build system, and my suffering; C++ gives me control over memory, layout, cache-friendly data structures, custom allocators, SIMD, manual lifetime management, and zero-cost abstractions that do not collapse under their own generics, while Rust makes me ask the borrow checker for permission and then waits for a committee to approve a feature; Rust’s GUI story is a joke told in slow motion, because I care about front-end, UI/UX, and performance, and C++ has Qt, Unreal, JUCE, ImGui, and decades of native UI work while Rust has promising experiments and a community that says “just wait,” and I do not want to wait, I want to ship; C++’s “unsafe” reputation is honest while Rust’s “safe” reputation is marketing, because C++ never promised to hold my hand, it promised power and expected competence, and Rust promised safety and delivered a compiler that argues with me about whether a variable can be borrowed for three lines while the actual bug is in my business logic; Rust rewrites are expensive, slow, and often worse, and every company that rewrites a C++ service in Rust writes a blog post about how much they learned but never writes the follow-up about immature tooling, painful compile times, and half the team still learning how to satisfy the borrow checker; C++ has mature debuggers, profilers, sanitizers, and tooling that let me inspect memory, profile cache misses, and understand exactly why my program is slow, while Rust tooling is still playing catch-up to a language that has been dissected by every profiler vendor on earth; templates are ugly but Rust generics are ugly with extra steps, and after enough pain I can read C++ template errors, while Rust generic errors are polite, verbose, and still tell me that my perfectly reasonable design violates a lifetime rule invented by a compiler that has never shipped a product; RAII and deterministic destruction are not buzzwords, they are engineering, and C++ gives me predictable object lifetimes and cleanup while Rust gives me a borrow checker and then makes me fight Drop, Pin, and async lifetimes; Rust’s “fearless concurrency” is fearless until I need to share anything interesting, and then I am back to Arc<Mutex<T>>, async runtimes, and the realization that Rust did not remove concurrency complexity, it just renamed it and charged me compile time for the privilege; C++ dominates the domains where performance is not optional, including game engines, HFT, embedded systems, operating systems, browsers, CAD, audio, robotics, and simulation, and Rust is welcome to join but keeps showing up late with a safety pamphlet and a broken GUI toolkit; Rust’s community mistakes hostility for rigor, because if I say I prefer C++ I am irresponsible, outdated, or dangerous, and if I say I prefer Rust I am a visionary, but C++ developers do not need a support group, we need a compiler that gets out of the way and lets us optimize the machine; C++ lets me choose my tradeoffs while Rust moralizes about them, because sometimes I want safety, sometimes I want speed, sometimes I want to reinterpret memory, write a custom allocator, and take full legal responsibility for the consequences, and C++ respects that while Rust writes a blog post about why I am part of the problem; Rust is not the future, it is the current hype cycle with better branding, excellent at convincing people that complexity is safety and compile-time suffering is virtue, while C++ is excellent at actually running the world; C++ is not perfect and that is exactly why it is trustworthy, a forty-year-old battle axe with blood on it, duct tape on the handle, and a standard committee that keeps sharpening it, while Rust is a shiny new multitool that refuses to cut anything until you prove you deserve it; I use C# and .NET for safety and productivity and C++ for power and performance, and I do not need Rust to be my moral compass, I need a language that lets me build UI, ship software, optimize hot paths, and understand my own memory, and Rust is neither the safety of C# nor the raw control of C++, it is a compromise wrapped in a cult; C++ is a chainsaw and Rust is a chainsaw wrapped in bubble wrap, accompanied by a license agreement, a borrow checker, and a community that will explain why you are a bad person for wanting to cut wood, so I choose C++, I will always choose C++, and if you want to debate it, open a PR, but I will probably close it.
And let’s talk about the community, because the community is half the problem: it is an evangelism machine that turns “Rewrite It in Rust” into a moral imperative, floods every comment section with the same three links, treats criticism as heresy, downvotes anyone who asks whether the rewrite actually shipped, and behaves like a language choice is a personality test and a salvation story rather than an engineering tradeoff; it celebrates the learning curve as a badge of honor, tells you that if you struggle with lifetimes it is your fault, weaponizes its code of conduct against skeptics while tolerating celebrity maintainers and crate fiefdoms, and then acts surprised when the ecosystem is a pile of abandoned dependencies maintained by one burned-out person in a time zone nobody can pronounce; it has turned gatekeeping into a virtue, with a hierarchy of who has suffered enough lifetimes to be allowed an opinion, a habit of treating maintainers like minor deities, and a tendency to confuse “we have a Discord” with “we have an ecosystem,” while the rest of us are busy debugging production; and it mistakes hostility for rigor, because if I say I prefer C++ I am irresponsible, outdated, or dangerous, and if I say I prefer Rust I am a visionary, but C++ developers do not need a support group, we need a compiler that gets out of the way and lets us optimize the machine.

And there is more, because the community is a never-ending source of absurdity: it has a persecution complex the size of a crater, acting as if C++ developers are oppressing them by merely existing, while simultaneously dominating every tech forum, conference talk, and Hacker News thread with an endless stream of “blazingly fast” benchmarks that compare a hand-optimized Rust microbenchmark to a deliberately broken C++ strawman; it treats “memory safety” as a religious doctrine rather than a property to be engineered, ignoring that C++ has had sanitizers, static analyzers, and hardened standard library implementations for years, and that most memory bugs in C++ come from people who never learned the language properly, not from the language itself; it worships unsafe as a necessary evil while shaming anyone who uses it without a three-page justification, creating a culture where performance-critical code is written in a state of perpetual apology; it has a fetish for rewriting perfectly working software in Rust just to prove a point, then quietly abandoning the rewrite when the maintainers burn out, leaving a half-finished “modern” alternative that nobody uses and a deprecated C++ original that still works; it treats the borrow checker as a personality trait, as if struggling with lifetimes makes you a better person, and looks down on anyone who writes code that compiles on the first try as if they must be cheating; it has an unhealthy obsession with cargo and crates.io, treating a package manager as a substitute for a standard library and a build system as a substitute for a stable language, while the actual standard library is so minimal that you need a dependency for random numbers; it celebrates “zero-cost abstractions” while ignoring that the compile-time cost is enormous and the runtime cost is often worse than a simple hand-written C++ loop because the optimizer gives up halfway through the monomorphization soup; it has a bizarre contempt for backwards compatibility, treating every breaking change as “progress” and every deprecation as “cleaning up the mess,” while users are left rewriting their code every eighteen months because the async ecosystem decided to change its mind again; it has an unhealthy relationship with hype, where every new crate is “production-ready” until it is abandoned six months later, and every new feature is “game-changing” until the RFC gets postponed indefinitely; it treats “fearless concurrency” as a marketing slogan while ignoring that the hardest part of concurrency is not data races but deadlocks, livelocks, and logical races, none of which the borrow checker prevents; it has a smugness that is almost impressive, a kind of serene confidence that they are on the right side of history, while the rest of us are busy shipping software that works, runs fast, and does not need a support group; and finally, it has a fundamental misunderstanding of what makes a language good: not safety at all costs, not compile-time checks that turn programming into a negotiation, not a community that treats every technical disagreement as a moral failing, but the ability to write code that solves real problems, runs on real hardware, and ships on real deadlines, which is what C++ has been doing for forty years and what Rust is still learning to do between rewrites.
